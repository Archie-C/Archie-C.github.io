Building a Neural Network in PyTorch

Build a neural network in PyTorch and follow the calculations behind its predictions.

Mathematical equations in code

We have seen how a neural network builds a prediction by composing layers. Each fully connected layer takes its inputs, forms weighted sums, adds biases and applies an activation function:

$$\mathbf{z}=h(\mathbf{W}\mathbf{x}+\mathbf{b}).$$

To implement this calculation, we need numerical arrays for the inputs, weights, biases and activations, and operations to combine them. The hidden units are the learnable basis functions we met earlier: their parameter values determine the features passed to the next layer.

PyTorch is a Python library for numerical computation and deep learning. It provides tools for building networks and calculating gradients automatically. We will explore automatic differentiation later. PyTorch can perform calculations on CPUs and supported GPUs, but we will use the CPU in this note. The mathematics stays the same; PyTorch gives us convenient ways to express and execute it.

Introduction to tensors

PyTorch's main data structure is the torch.Tensor. Like a NumPy array, a tensor stores numbers in an array with a shape and a data type. We can create one from a Python list using torch.tensor, or from a NumPy array using torch.from_numpy:

import torch
import numpy as np

x = torch.tensor([1.0, 2.0])
a = np.array([3.0, 4.0], dtype=np.float32)
y = torch.from_numpy(a)
print(x, y)  # tensor([1., 2.]) tensor([3., 4.])

A scalar has no dimensions, a vector has one and a matrix has two. The .shape attribute tells us the size of each dimension:

scalar = torch.tensor(2.0)                  # shape: ()
vector = torch.tensor([1.0, 2.0])            # shape: (2,)
matrix = torch.tensor([[1.0, 2.0], [3.0, 4.0]])  # shape: (2, 2)
print(scalar.shape, vector.shape, matrix.shape)

Arithmetic such as addition and multiplication with * works element by element. The @ operator instead performs matrix multiplication, combining entries across a shared dimension:

x = torch.tensor([1.0, 2.0])
y = torch.tensor([3.0, 4.0])
W = torch.tensor([[1.0, 2.0], [3.0, 4.0]])
print(x + y)  # tensor([4., 6.])
print(x * y)  # tensor([3., 8.])
print(W @ x)  # tensor([5., 11.])

Tensors also have a data type, available through .dtype. Two common types are torch.float32 for floating-point numbers and torch.int64 for integers. Neural-network inputs and parameters are typically floating point because weights and activations can take fractional values and gradients are calculated for floating-point parameters. Integer tensors are useful for things such as class indices.

features = torch.tensor([1, 2], dtype=torch.float32)
labels = torch.tensor([0, 1], dtype=torch.int64)
print(features.dtype, labels.dtype)

For a CPU tensor that does not track gradients, .numpy() gives a NumPy array. To convert a tensor that tracks gradients, first use .detach(); if it is on a GPU, move it to the CPU with .cpu() as well. Conversions can share memory, so changing one array can change the other.

array = features.detach().cpu().numpy()
tensor = torch.from_numpy(array)
print(array, tensor)

Implementing a neuron manually

Let's start with one neuron. It takes a weighted sum of its inputs, adds a bias and applies an activation function:

$$z=h(\mathbf{w}^{\top}\mathbf{x}+b).$$

import torch

x = torch.tensor([1.0, 2.0])
w = torch.tensor([0.5, -1.0])
b = torch.tensor(2.0)
weighted_sum = w @ x          # 0.5(1) - 1(2) = -1.5
a = weighted_sum + b         # 0.5
z = torch.relu(a)            # max(0, 0.5)
print(z)                     # tensor(0.5000)

The @ operation calculates $\mathbf{w}^{\top}\mathbf{x}$, then we add $b$. Finally, torch.relu applies ReLU, returning zero for a negative value and the value itself otherwise. We chose the weights and bias by hand; later we will learn how to find them from data.

try it

Change the second input to 1. Before running the code, calculate the new weighted sum and predict the output after ReLU.

Implementing a hidden layer manually

A layer performs the same calculation for several neurons in parallel. For two inputs and three hidden neurons, we can put one neuron's weights in each row of $\mathbf{W}^{(1)}$:

$$\mathbf{z}=h(\mathbf{W}^{(1)}\mathbf{x}+\mathbf{b}^{(1)}).$$

import torch

x = torch.tensor([1.0, 2.0])                    # (2,)
W1 = torch.tensor([[0.5, -1.0],                # (3, 2)
                   [1.0, 1.0],
                   [-1.0, 0.5]])
b1 = torch.tensor([2.0, -1.0, -1.0])           # (3,)
a1 = W1 @ x + b1                               # (3,): [0.5, 2.0, -1.0]
z = torch.relu(a1)                             # (3,): [0.5, 2.0, 0.0]
print(z)  # tensor([0.5000, 2.0000, 0.0000])

Each row of W1 contains the two weights for one neuron, and each entry of b1 is its bias. One matrix multiplication calculates all three weighted sums. ReLU then acts elementwise, giving three hidden features. We can check the first neuron against the calculation above.

Adding an output layer

We can use those three features as inputs to an output neuron. For regression, we use an identity output activation, leaving the output layer's weighted sum unchanged:

$$\hat{y}=\mathbf{W}^{(2)}h(\mathbf{W}^{(1)}\mathbf{x}+\mathbf{b}^{(1)})+\mathbf{b}^{(2)}.$$

# Continue from the hidden-layer example above
W2 = torch.tensor([[1.0, -0.5, 2.0]])  # (1, 3)
b2 = torch.tensor([0.5])               # (1,)
prediction = W2 @ z + b2               # (1,)
print(prediction)  # tensor([0.])

Here z is the hidden layer's output and the output layer's input. The result is $1(0.5)-0.5(2)+2(0)+0.5=0$. A network can produce a prediction before its parameters have been trained, but there is no reason to expect that prediction to be useful yet.

Introducing torch.nn

Creating every weight matrix and bias vector ourselves becomes inconvenient as networks grow. torch.nn provides a collection of neural-network components. One of these is nn.Linear, which performs the affine transformation

$$\mathbf{a}=\mathbf{W}\mathbf{x}+\mathbf{b}.$$

Its in_features argument is the number of input features and out_features is the number of outputs. It does not apply an activation function; we add one separately, for example with nn.ReLU().

import torch
from torch import nn

layer = nn.Linear(in_features=2, out_features=3)
x = torch.tensor([1.0, 2.0])
print(layer.weight, layer.weight.shape)  # weights: (3, 2)
print(layer.bias, layer.bias.shape)      # biases: (3,)
a = layer(x)                             # affine transformation
z = nn.ReLU()(a)                         # apply ReLU
print(a, z)

PyTorch initialises the weights and biases automatically, so their values and the output will generally differ between runs. Their shapes still match the manual layer: one row of weights and one bias per output.

Building a network with nn.Sequential

nn.Sequential connects modules in order, passing each module's output directly to the next. We can construct the same architecture as before:

import torch
from torch import nn

model = nn.Sequential(
    nn.Linear(2, 3),
    nn.ReLU(),
    nn.Linear(3, 1)
)
print(model)
x = torch.tensor([1.0, 2.0])
print(model(x))  # one complete forward pass
print(list(model.parameters()))

The first linear layer maps two inputs to three values. ReLU turns these into hidden features, and the second linear layer maps the three features to one regression output. print(model) displays the architecture; model.parameters() gives access to its current weights and biases. The architecture specifies the operations and shapes, while the parameter values determine the particular function computed.

Random initialisation means predictions can differ between runs. We can control the random seed or set the parameters explicitly. To compare with our manual calculation, copy its values into the two linear modules. torch.no_grad() lets us assign them without recording the assignment for gradient calculations, and copy_ copies values into the existing parameters:

# Continue from the manual layer and nn.Sequential examples
with torch.no_grad():
    model[0].weight.copy_(W1)
    model[0].bias.copy_(b1)
    model[2].weight.copy_(W2)
    model[2].bias.copy_(b2)

manual = W2 @ torch.relu(W1 @ x + b1) + b2
print(manual, model(x))          # both tensor([0.])
print(torch.allclose(manual, model(x)))  # True

torch.allclose checks whether two tensors agree within a numerical tolerance. The modules now have the same architecture and parameter values as the manual network.

Working with batches of observations

We often process several observations together. For $N$ observations with $D$ features each, we arrange one observation per row:

$$\mathbf{X}\in\mathbb{R}^{N\times D}.$$

The first dimension is the batch dimension. A single input vector has shape (2,); a batch of three observations with two features has shape (3, 2):

# Continue with model from above
X = torch.tensor([[1.0, 2.0],
                  [0.0, 1.0],
                  [2.0, 0.0]])
predictions = model(X)
print(X.shape)            # torch.Size([3, 2])
print(predictions.shape)  # torch.Size([3, 1])
print(predictions)        # [[0.], [1.5], [3.]] (values shown without grad information)

nn.Linear transforms the last, feature dimension and preserves the batch dimension. With one output neuron, the result has shape (N, 1). In matrix notation for a batch, the first affine operation is $\mathbf{X}(\mathbf{W}^{(1)})^\top+\mathbf{b}^{(1)}$, with the bias added to each row.

A common mistake is to confuse the number of observations with the number of features. nn.Linear(2, 3) expects two features in the last dimension, regardless of batch size. Transposing this example to shape (2, 3) would give it three features per observation and cause a shape error.

Computing a loss function

A prediction can be compared with a target using a loss function. For our regression network, nn.MSELoss() calculates the mean squared error introduced in the outputs and loss functions note: $\frac{1}{N}\sum_{n=1}^{N}(\hat{y}_n-y_n)^2$ for one output per observation.

# Continue with model and X from above
predictions = model(X)                       # (3, 1)
targets = torch.tensor([[1.0], [0.0], [2.0]])  # (3, 1)
loss = nn.MSELoss()(predictions, targets)
print(loss)  # approximately 1.4167

Predictions and targets should have matching shapes. A target with shape (3,) and predictions with shape (3, 1) can be broadcast into a (3, 3) comparison instead of pairing each prediction with its own target. This is not the loss we intended.

For classification, PyTorch also provides losses that combine the output activation with the loss calculation. Both examples below take logits, so we do not apply sigmoid or softmax to the outputs first:

# Binary classification: floating-point targets, same shape as logits
binary_logits = torch.tensor([[0.2], [-1.0], [1.5]])  # (3, 1)
binary_targets = torch.tensor([[1.0], [0.0], [1.0]]) # (3, 1)
binary_loss = nn.BCEWithLogitsLoss()(binary_logits, binary_targets)

# Multiclass classification: one integer class index per observation
class_logits = torch.tensor([[1.0, 0.5, -1.0], [0.0, 2.0, 1.0]])  # (2, 3)
class_targets = torch.tensor([0, 2], dtype=torch.int64)             # (2,)
class_loss = nn.CrossEntropyLoss()(class_logits, class_targets)
print(binary_loss, class_loss)

For standard multiclass cross-entropy, each target is the index of the correct class, between zero and the number of classes minus one. The logits have one entry per class for each observation.

A first look at trainable parameters

PyTorch automatically tracks parameters belonging to modules such as nn.Linear. model.parameters() provides the parameters, while model.named_parameters() also gives each one a name:

# Continue with model from above
for name, parameter in model.named_parameters():
    print(name, parameter.shape, parameter)

count = sum(p.numel() for p in model.parameters() if p.requires_grad)
print(count)  # 13

requires_grad=True means PyTorch tracks operations on that parameter so that gradients can be calculated for it. numel() counts the entries in a tensor. For $D=2$ inputs, $M=3$ hidden neurons and $K=1$ output, this agrees with our earlier parameter-count formula:

$$P=M(D+1)+K(M+1)=3(2+1)+1(3+1)=13.$$

Training aims to find parameter values that minimise a loss. PyTorch can calculate the gradients needed for this automatically; we will use that capability shortly.

Worked example: a complete neural network

Let's put the pieces together. This example creates a regression network, makes predictions for a small batch and compares them with targets. A fixed seed makes the random initialisation reproducible in the same environment.

import torch
from torch import nn

torch.manual_seed(42)
model = nn.Sequential(
    nn.Linear(2, 3),
    nn.ReLU(),
    nn.Linear(3, 1)
)

X = torch.tensor([[1.0, 2.0], [0.0, 1.0], [2.0, 0.0]])
targets = torch.tensor([[1.0], [0.0], [2.0]])
predictions = model(X)
loss = nn.MSELoss()(predictions, targets)
count = sum(p.numel() for p in model.parameters() if p.requires_grad)

print("Predictions:", predictions)
print("Loss:", loss.item())
print("Trainable parameters:", count)  # 13

torch.manual_seed sets the seed before the layers are created. Each row of X is one observation; each row of targets is its corresponding value. Calling the model performs the forward pass, and nn.MSELoss compares the resulting predictions with the targets. loss.item() extracts the single numerical value from the loss tensor.

We have not used the targets to change any parameters. The predictions therefore come from the initial parameter values, and the model has not learned from these observations yet.

Training Our First Neural Network

We have built a network and measured its loss, but we have not yet changed its parameters to improve its predictions. Let's do that now with a small regression problem. We will generate observations using $y=x^2$ and train a network to approximate this nonlinear relationship.

The example below uses PyTorch and Matplotlib. If you need to install them, follow the installation instructions for your environment. The data are generated in the code, so no dataset download is needed.

import torch
from torch import nn
import matplotlib.pyplot as plt

torch.manual_seed(42)

# Generate 41 observations, each with one input and one target.
X = torch.linspace(-1.0, 1.0, 41).reshape(-1, 1)
targets = X ** 2

model = nn.Sequential(
    nn.Linear(1, 16),
    nn.ReLU(),
    nn.Linear(16, 1)
)
loss_function = nn.MSELoss()
optimizer = torch.optim.SGD(model.parameters(), lr=0.05)

# Save predictions before any parameters are updated.
with torch.no_grad():
    predictions_before = model(X).clone()

losses = []
epochs = 2000
for epoch in range(epochs):
    predictions = model(X)
    loss = loss_function(predictions, targets)
    losses.append(loss.item())

    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

with torch.no_grad():
    predictions_after = model(X)
    final_loss = loss_function(predictions_after, targets).item()

print(f"Initial loss: {losses[0]:.6f}")
print(f"Final loss:   {final_loss:.6f}")

fig, axes = plt.subplots(1, 2, figsize=(10, 4))
axes[0].scatter(X[:, 0].numpy(), targets[:, 0].numpy(),
                label="Training data", color="black", s=15)
axes[0].plot(X[:, 0].numpy(), predictions_before[:, 0].numpy(),
             label="Before training", linestyle="--")
axes[0].plot(X[:, 0].numpy(), predictions_after[:, 0].numpy(),
             label="After training")
axes[0].set_xlabel("x")
axes[0].set_ylabel("y")
axes[0].legend()

axes[1].plot(range(1, epochs + 1), losses)
axes[1].set_xlabel("Epoch")
axes[1].set_ylabel("Mean squared error")
axes[1].set_title("Training loss")
plt.tight_layout()
plt.show()

torch.linspace creates evenly spaced inputs between $-1$ and $1$. We use reshape(-1, 1) to arrange them as a batch with shape (41, 1); the targets have the same shape. The network has one input, 16 hidden ReLU neurons and one output. Its hidden neurons provide features that can be combined to approximate the curve.

torch.optim.SGD creates an optimiser that will update the model's parameters. The learning rate lr controls the size of its updates. Each epoch in this example uses the whole batch once. Within each epoch, we calculate predictions and their MSE, then:

  1. optimizer.zero_grad() clears the gradients left over from the previous epoch. PyTorch otherwise accumulates them.
  2. loss.backward() calculates gradients of the loss with respect to the parameters. These describe how the loss changes as the parameters change.
  3. optimizer.step() uses those gradients to update the parameters.

We record the loss before the update in each epoch, and calculate the final loss again after the last update. torch.no_grad() tells PyTorch that we do not need gradients when saving predictions for the plots. The first plot compares the initial and trained predictions with the data; the second shows the training loss across epochs. With the fixed seed and these settings, the loss should decrease and the fitted curve should follow the data more closely.

These plots show how well the network fits the observations it trained on. They do not tell us how well it will predict new observations; we would need separate data to investigate that.

Summary
