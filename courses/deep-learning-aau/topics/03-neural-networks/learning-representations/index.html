Representation Learning.

The hidden layers of a neural network learn features as they make predictions. Let's look at what these features represent and how we can use them for other tasks.

What this note covers

  • Learned representations and embeddings
  • Learning features from supervised and self-supervised tasks
  • Reusing pretrained features and fine-tuning
  • Limitations of learned representations

Predictions and representations

In Introduction to learning features, we started with basis functions that we chose ourselves. For example, we could add $x^2$ as a feature in a regression model. We then introduced learnable basis functions so that the model could find useful features from the data.

In a neural network, the hidden layers give us a way to learn these transformations. Recall that the output of layer $\ell$ is:

$$\mathbf{z}^{(\ell)} = h^{(\ell)}\left(\mathbf{W}^{(\ell)}\mathbf{z}^{(\ell-1)} + \mathbf{b}^{(\ell)}\right), \qquad \mathbf{z}^{(0)}=\mathbf{x}.$$

Here $\mathbf{W}^{(\ell)}$ and $\mathbf{b}^{(\ell)}$ are the weights and biases of the layer, and $h^{(\ell)}$ is its activation function. The vector $\mathbf{z}^{(\ell)}$ contains the features calculated by that layer. We call it a learned representation of the original input $\mathbf{x}$.

Each hidden layer receives the representation from the previous layer, so different layers can represent the same input in different ways. The output layer then uses the final hidden representation to make a prediction.

We call the process of learning useful transformations of the data representation learning. Rather than constructing all the features ourselves, we allow the network to learn them. What makes a representation useful depends on the task we want to solve.

What makes a representation useful?

Suppose we want to classify images of handwritten digits. Two images can both show a 3, but the digit may be in a different position, have a different size or rotation, or be written in a different style. These changes affect the pixel values, even though the class is the same.

For this task, we want the representation to preserve information that helps distinguish digits, while reducing the importance of variation that does not change the class. For example, a useful transformation might map two differently written 3s to similar feature vectors, while making 3s and 8s easier to distinguish.

If the features make the classes easier to separate, a simple output layer may be enough to classify them. The illustration below shows one possible result. The points still overlap: a particular arrangement, or even a useful notion of distance, is not guaranteed by training a classifier.

Which differences should be ignored depends on the task. For digit classification, handwriting style might be irrelevant; for identifying who wrote the digit, it could be useful. The training objective shapes the representation, but does not guarantee that every network will group examples in this way.

Embeddings and representation spaces

We often call a vector representation of an input an embedding. If we write the hidden layers as a function $f_{\boldsymbol{\theta}}$, with parameters $\boldsymbol{\theta}$, we can write:

$$\mathbf{z}=f_{\boldsymbol{\theta}}(\mathbf{x}).$$

The input is $\mathbf{x}$, and the embedding $\mathbf{z}$ is the feature vector returned by the learned transformation. The set of possible vectors is the representation space, often called the embedding space. The embedding is not yet a class prediction; we can use it as an input to a classifier.

For example, a $28\times28$ image has 784 pixel values. A network could map it into a vector with 16 components:

$$f_{\boldsymbol{\theta}}:\mathbb{R}^{784}\rightarrow\mathbb{R}^{16}.$$

The 16 components are learned combinations of the inputs; they do not need to correspond to individual pixels or have an obvious interpretation. Embeddings are not limited to two or three dimensions as in our plot. They can contain hundreds or thousands of components. The transformation can reduce the number of dimensions, as above, but it can also keep the same number or increase it.

One way to compare two embeddings is Euclidean distance:

$$d(\mathbf{z}_i,\mathbf{z}_j)=\|\mathbf{z}_i-\mathbf{z}_j\|_2.$$

This measures the distance between the two points. Another common measure is cosine similarity:

$$\operatorname{sim}(\mathbf{z}_i,\mathbf{z}_j)=\frac{\mathbf{z}_i^\top\mathbf{z}_j}{\|\mathbf{z}_i\|_2\|\mathbf{z}_j\|_2}.$$

Cosine similarity compares the directions of two nonzero vectors, rather than the distance between their endpoints. It is undefined if either vector is zero. Two vectors pointing in the same direction have cosine similarity 1, even if their lengths differ.

important

Neither distance nor cosine similarity is automatically meaningful just because the vectors came from a network. We need to consider the data and objective used to learn the representation, and whether they support the comparison we want to make.

Learning representations through supervised learning

We do not need to tell a network explicitly to find a particular edge or curve. Instead, we can train it to make a prediction and let it learn features that help with that task. For a classifier, we can separate the hidden layers and output layer as:

$$\mathbf{z}=f_{\boldsymbol{\theta}}(\mathbf{x}), \qquad \hat{\mathbf{y}}=g_{\mathbf{w}}(\mathbf{z}).$$

Here $f_{\boldsymbol{\theta}}$ produces the representation and $g_{\mathbf{w}}$ uses it to produce the prediction. The parameters $\boldsymbol{\theta}$ belong to the hidden layers and $\mathbf{w}$ denotes the output layer's parameters, including its biases.

For a digit classifier, $\hat{\mathbf{y}}$ could contain the predicted probabilities for the ten digits. During training, we compare these probabilities with the labels using multiclass cross-entropy, as in the previous note. The loss provides a learning signal for both the output layer and the hidden layers. We will look at how parameters are updated later.

As the network learns to distinguish digits, its hidden features can become useful for that distinction. We do not prescribe those features individually, and a different prediction task or loss can lead to a different representation of the same images.

Reusing learned representations

Suppose we have a network trained to recognise many kinds of objects in photographs, and we now want to classify a smaller collection of plant images. Some features learned from the first task may also be useful for the second. Instead of learning every feature again from random initialisation, we can start with the existing network.

This is an example of transfer learning. We use the pretrained hidden layers as a feature extractor and attach a new output layer for the plant classes. The original output layer predicted the classes from the first task, so we replace it with one that matches the new targets.

Transfer learning can be particularly useful when we have relatively little labelled data for the new task. The pretrained features give us a starting point, but they are not guaranteed to help. If the source and target tasks or their data are very different, we need to check whether the transferred features are useful.

Frozen features and fine-tuning

Once we have attached a new output layer, we can decide which parameters to train. Two common approaches are:

Frozen feature extraction. We keep the pretrained parameters fixed and train only the new output layer. Each input is transformed using the same pretrained features throughout training. Since we learn fewer parameters, this can also be computationally cheaper.

Fine-tuning. We allow some or all of the pretrained parameters to change along with the new output layer. This lets the features adapt to the new task. The trade-off is that changing them may also alter useful features learned from the original task. Fine-tuning may need more data and computation than training only the output layer.

Learning representations without labels

So far we have used supervised learning: each training input comes with a target supplied for the prediction task. But we do not always have labels, and obtaining them can be expensive. We can also learn representations using information already present in unlabelled data.

In self-supervised learning, we construct a learning task from the data itself. For example, we might hide part of an image and ask a model to predict the missing part. To do this, it must use information from the visible pixels. Another approach is to learn representations that remain similar when we apply suitable transformations to an image.

One family of approaches is contrastive learning. The basic idea is to encourage related examples to have similar representations, while unrelated examples may be pushed apart. For example, two differently cropped or slightly rotated versions of the same photograph can form a positive pair. Other images can serve as negative examples in methods that use negative pairs.

The transformations should preserve information we expect to matter for the eventual task. Not all self-supervised methods are contrastive, and not all contrastive methods require explicit negative pairs. In either case, an abundance of unlabelled data can help us learn a representation before using labelled examples for a later task.

Worked example: using an embedding for a new task

Suppose a digit classifier maps each $28\times28$ image to a 16-dimensional representation and then predicts one of ten digits. We can write its original pipeline as:

$$\mathbf{x}\in\mathbb{R}^{784}\ \xrightarrow{\ f_{\boldsymbol{\theta}}\ }\ \mathbf{z}\in\mathbb{R}^{16}\ \xrightarrow{\ g_{\mathbf{w}}\ }\ \hat{\mathbf{y}}\in\mathbb{R}^{10}.$$

Now suppose our new task is to predict whether a digit is even or odd. We remove the original output layer, extract $\mathbf{z}$ from the hidden network, and attach a new binary classifier:

$$\mathbf{x}\in\mathbb{R}^{784}\ \xrightarrow{\ f_{\boldsymbol{\theta}}\ }\ \mathbf{z}\in\mathbb{R}^{16}\ \xrightarrow{\ g_{\mathbf{v}}\ }\ p(\text{even}\mid\mathbf{x})\in(0,1).$$

For example, the new classifier could apply sigmoid to $\mathbf{v}^\top\mathbf{z}+b$. It uses 16 learned features rather than 784 pixel values. We can freeze $f_{\boldsymbol{\theta}}$ and train only $\mathbf{v}$ and $b$, or fine-tune some or all of $f_{\boldsymbol{\theta}}$ as well. We should still check performance on held-out examples for the new task.

To see how we might compare embeddings, let's use two-dimensional vectors for a small calculation. These are only illustrative; the digit network above uses 16 dimensions. Suppose:

$$\mathbf{z}_1=\begin{bmatrix}1\\2\end{bmatrix},\qquad \mathbf{z}_2=\begin{bmatrix}2\\2\end{bmatrix}.$$

Their Euclidean distance and cosine similarity are:

$$d(\mathbf{z}_1,\mathbf{z}_2)=\sqrt{(1-2)^2+(2-2)^2}=1,\qquad \operatorname{sim}(\mathbf{z}_1,\mathbf{z}_2)=\frac{6}{\sqrt{5}\sqrt{8}}\approx0.949.$$

The points are one unit apart, and their vectors point in similar directions. Whether either number tells us anything useful about the images depends on how the representation was learned.

Limitations of learned representations

A learned representation is not automatically meaningful, interpretable or useful for another task. It depends on the training data, the prediction task, the architecture and the loss. If a feature helps minimise the training loss, the network may use it even if it is not the feature we expected.

For example, a classifier might learn to associate a class with the background in its training images instead of the object itself. This shortcut could fail when the background changes. Similarly, a representation that discards handwriting style to classify digits may no longer contain enough information to identify the writer.

Plots like fig 2 can help us explore representations, but an embedding with many dimensions must be projected down to two dimensions to draw it this way. That projection can distort distances and relationships, so we should be careful about drawing conclusions from the plot alone.

Summary

Neural networks learn representations as well as predictions. These representations are shaped by the task and data used to learn them, and can sometimes be reused for a new problem. Whether we freeze or adapt the features, we need to check how useful they are for the new task.
