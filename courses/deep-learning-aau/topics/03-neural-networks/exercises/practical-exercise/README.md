# Rocket control exercise materials

Read `Neural_Network_Exercises_2026.pdf` for the questions, practical task and
submission requirements. Use Python 3.11 or newer for the notebook.

1. Extract the ZIP and open a terminal in the extracted `rocket-control` folder.
2. Create a virtual environment: `python -m venv .venv`.
3. Activate it with `.venv\Scripts\Activate.ps1` in Windows PowerShell, or
   `source .venv/bin/activate` on macOS/Linux.
4. Install the dependencies: `python -m pip install -r requirements.txt`.
5. Start Jupyter with `python -m jupyter notebook` and open `train.ipynb`.
   Keep the notebook, model, dataset and simulator files in the same folder.

`model.py` contains an incomplete starter network. Complete its thrust and gimbal
output activation functions before training. The model receives 12 raw physical
observations and must return a tensor of shape `(batch, 2)`, with thrust in
`[0, 1]` and gimbal in `[-1, 1]`. The `run_id`, `step` and `success` columns in
`landings.csv` are metadata, not model inputs. Split data by whole flights as
shown in the notebook.

The notebook trains the model, evaluates predictions, simulates local flights,
optionally exports a replay JSON and saves `weights.safetensors`. You can import
the replay into the exercise page's **Import JSON** viewer. The `rocket_*.py`
files provide the simulator; you do not need to edit them. `physics.pdf` is
optional background for interpreting the physics and designing features.

Make two informed model changes and document your reasoning and experimental
comparisons in `train.ipynb`. Normalisation and regularisation are allowed but
do not count as either of the two changes. Keep a separate copy of the model
after the first change and another after the final change. See the exercise PDF
for the Moodle submission, including the PDF answers to Questions 1-3.

For online evaluation, upload exactly `model.py` and its matching
`weights.safetensors`. Weights are generated by your training run and are not
included in this download. The online evaluator uses ten hidden flights; local
public scenarios help you develop the controller but do not predict its hidden
test score. Aim for successful landings and compare simulated outcomes as well
as prediction losses.
