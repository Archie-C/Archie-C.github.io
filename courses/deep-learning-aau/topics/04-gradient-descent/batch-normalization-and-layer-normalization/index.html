Batch normalisation and layer normalisation.

Which values should we use to normalise the intermediate representations inside a neural network?

What this note covers

  • Normalising intermediate values and the role of learnable scale and shift
  • Batch statistics during training and running statistics during inference
  • Layer normalisation, normalisation axes and architectural choices
  • Optimisation, limitations and practical considerations

Why normalise inside a network?

In the previous note, we standardised each input feature using its training mean and standard deviation, $\tilde x_i=(x_i-\mu_i)/\sigma_i$. Comparable input scales can make some optimisation problems easier. But what happens after those inputs pass through several layers?

For layer $l$, the notation from the previous note gives

$$a_i^{(l)}=\sum_j w_{ij}^{(l)}z_j^{(l-1)}+b_i^{(l)},\qquad z_i^{(l)}=\phi(a_i^{(l)}).$$

Each layer transforms the preceding representation. Its weights, biases and activation function determine the values passed onwards, so standardised inputs do not guarantee comparable pre-activation scales later in the network. As parameters change, these intermediate distributions can change too. Very large or small signals can make optimisation harder, and deep networks can encounter vanishing or exploding gradients. Forward signal size and backward gradient size are related, but controlling one does not automatically control the other.

Initialisation helps set useful signal scales at the start of training. A normalisation operation inside the model can continue to affect intermediate scales as the parameters change. Input normalisation instead uses training-dataset statistics to preprocess features; internal normalisation is part of the network computation, where the values being normalised themselves change during learning. Batch and layer normalisation differ principally in which values are grouped when computing their statistics.

Batch normalisation

Consider a mini-batch of $B$ examples and a fully connected layer with $M$ units. Write $a_{ni}$ for the pre-activation of unit $i$ for example $n$; the layer superscript is omitted for clarity. Batch normalisation calculates a separate mean and variance for each unit across the examples:

$$\boxed{\mu_i=\frac1B\sum_{n=1}^{B}a_{ni}},\qquad \boxed{\sigma_i^2=\frac1B\sum_{n=1}^{B}(a_{ni}-\mu_i)^2},\qquad \boxed{\hat a_{ni}=\frac{a_{ni}-\mu_i}{\sqrt{\sigma_i^2+\epsilon}}}.$$

Each column is a different feature, which may have its own scale; summing over $n$ measures that feature across the current batch. Subtracting its mean centres the column, while dividing by its standard deviation rescales the deviations. The divisor $B$ describes the variance of the values actually being normalised, rather than an unbiased estimate with divisor $B-1$.

A small positive $\epsilon$ prevents division by zero and limits amplification when variance is tiny. Here it is inside the square root. Adding it outside would define a different denominator, particularly for small variances; implementations must use their own convention consistently. The normalised column has mean exactly zero up to rounding, and variance $\sigma_i^2/(\sigma_i^2+\epsilon)$: close to one when $\sigma_i^2\gg\epsilon$, but not exactly one. A constant column becomes zero. Normalisation can be placed at different points; we use pre-activations as the main example.

Worked example

Let rows be examples and columns be units:

$$\mathbf A=\begin{pmatrix}1&3&5\\5&9&1\end{pmatrix}.$$

The column means are $(1+5)/2=3$, $(3+9)/2=6$ and $(5+1)/2=3$. Their variances are $((1-3)^2+(5-3)^2)/2=4$, $((3-6)^2+(9-6)^2)/2=9$ and $((5-3)^2+(1-3)^2)/2=4$. With $\epsilon=0$ only for this nonzero-variance illustration, division by $(2,3,2)$ gives

$$\hat{\mathbf A}_{\mathrm{BN}}=\begin{pmatrix}-1&-1&1\\1&1&-1\end{pmatrix}.$$

Each column contains one $-1$ and one $1$, so its mean is zero and variance is one. Practical calculations retain a positive $\epsilon$.

Learnable scale and shift

Forcing every feature to remain centred and have unit variance could restrict useful representations. Batch normalisation therefore commonly adds trainable parameters $\gamma_i$ and $\beta_i$ for each feature:

$$\boxed{\tilde a_{ni}=\gamma_i\hat a_{ni}+\beta_i}.$$

These parameters are learned alongside weights and biases. If $\gamma_i=1$ and $\beta_i=0$, this step leaves the normalised value unchanged. Otherwise it provides a direct, learned scale and offset. Normalisation still determines how the result depends on the current batch statistics; the affine transformation gives the network control over the resulting representation. Its outputs need not have zero mean or unit variance.

For a normalised feature, $\mathbb E[\tilde a_i]=\gamma_i\mathbb E[\hat a_i]+\beta_i=\beta_i$ and $\operatorname{Var}(\tilde a_i)=\gamma_i^2\operatorname{Var}(\hat a_i)$. Thus its standard deviation is approximately $|\gamma_i|$, even when $\gamma_i$ is negative. For example, with $\hat{\mathbf a}_1=(-1,1)^\mathsf T$, $\gamma_1=2$ and $\beta_1=1$, the result is $(-1,3)^\mathsf T$: its centre moves to one and its spread doubles.

Batch normalisation during training

One common arrangement is linear transformation $\rightarrow$ batch normalisation $\rightarrow$ activation. For each mini-batch, the linear layer computes its pre-activations; the normalisation layer computes per-feature means and variances, centres and rescales the values, then applies $\gamma$ and $\beta$. The activation function receives the transformed values. Other placements are possible, including normalising activations, and change what is being normalised.

The next mini-batch usually has different statistics. Consequently, the normalised value of a fixed example can change when its companions change. Try editing the second row in figure 2: batch normalisation of the first row changes, while layer normalisation does not. This batch dependence introduces stochasticity in addition to the randomness of mini-batch gradient estimates. Smaller batches often give noisier, less representative statistics; larger batches tend to give more stable estimates, although composition and data distribution matter too.

When too few values contribute to a statistic, it may contain little useful information. With a single value, the centred result is zero. For convolutional batch normalisation the effective number can include spatial positions as well as examples, so it is not always just the batch size. The operation is differentiable for positive $\epsilon$, and gradient-based training optimises its scale and shift along with the rest of the network. The full backward calculation belongs in the next topic.

Batch normalisation during inference

At inference, predictions should generally not depend on which other examples happen to be evaluated together. A single example also provides no useful fully connected batch variance. Conventional batch normalisation therefore uses stored estimates accumulated during training, rather than the current inference batch.

One conceptual exponential moving average, with $0\leq\alpha<1$, is

$$\mu_i^{\mathrm{running},t}=\alpha\mu_i^{\mathrm{running},t-1}+(1-\alpha)\mu_i^{\mathrm{batch},t},\qquad v_i^{\mathrm{running},t}=\alpha v_i^{\mathrm{running},t-1}+(1-\alpha)v_i^{\mathrm{batch},t}.$$

For instance, $\alpha=0.9$, an old mean of $4$ and a batch mean of $6$ yield $4.2$. The old estimate retains weight $0.9$ and the new observation contributes $0.1$. The precise variance estimator, initialisation and meaning of a framework's “momentum” can differ. The current batch statistics normalise the training batch; the running estimates are accumulated model state, not parameters directly optimised by gradient descent.

In evaluation mode the stored values are fixed, and the learned affine parameters are still applied:

$$\hat a_i=\frac{a_i-\mu_i^{\mathrm{running}}}{\sqrt{v_i^{\mathrm{running}}+\epsilon}},\qquad \tilde a_i=\gamma_i\hat a_i+\beta_i.$$

For stored mean $4$, variance $9$ and $a=10$, neglecting $\epsilon$ gives $\hat a=2$. With $\gamma=1.5$ and $\beta=-1$, $\tilde a=2$. No other inference examples are needed. Using batch statistics at inference can make predictions depend on batch composition; failing to update running state leaves unrepresentative estimates. Evaluating in the wrong mode can therefore give misleading metrics as well as unexpected predictions.

Layer normalisation

Batch dependence motivates a different grouping: calculate statistics across the features of each example. For example $n$ with $M$ features,

$$\boxed{\mu_n=\frac1M\sum_{i=1}^{M}a_{ni}},\qquad \boxed{\sigma_n^2=\frac1M\sum_{i=1}^{M}(a_{ni}-\mu_n)^2},\qquad \boxed{\hat a_{ni}=\frac{a_{ni}-\mu_n}{\sqrt{\sigma_n^2+\epsilon}}}.$$

Now $n$ is fixed and the sum runs across $i$: we centre and rescale each row instead of each column. The same affine form $\tilde a_{ni}=\gamma_i\hat a_{ni}+\beta_i$ is commonly used, with parameters associated with feature coordinates and shared across examples.

Worked example

For the first row $(1,3,5)$, $\mu_1=3$ and $\sigma_1^2=(4+0+4)/3=8/3$. For the second $(5,9,1)$, $\mu_2=5$ and $\sigma_2^2=(0+16+16)/3=32/3$. With $\epsilon=0$ for this illustration,

$$\hat{\mathbf A}_{\mathrm{LN}}=\begin{pmatrix}-\sqrt{3/2}&0&\sqrt{3/2}\\0&\sqrt{3/2}&-\sqrt{3/2}\end{pmatrix},\qquad \hat{\mathbf A}_{\mathrm{BN}}=\begin{pmatrix}-1&-1&1\\1&1&-1\end{pmatrix}.$$

The first row's deviations $(-2,0,2)$ are divided by $\sqrt{8/3}$; the second row's $(0,4,-4)$ by $\sqrt{32/3}$. The same input produces different results because the groups used for the statistics differ. Figure 2 lets you inspect both calculations with positive $\epsilon$.

Comparing batch and layer normalisation

For $\mathbf A\in\mathbb R^{B\times M}$, batch normalisation groups examples for each feature; layer normalisation groups features for each example. Change the second row in figure 2 while keeping $(1,3,5)$ fixed. Batch statistics in the affected columns change, generally changing the first row's batch-normalised values. The first row's layer statistics remain $3$ and $8/3$, so its layer-normalised values stay fixed. This remains true in both training and inference when the selected feature dimensions are normalised independently for each example.

Layer normalisation generally needs no running estimates: it calculates statistics from the current example in both phases. This is useful with variable batch sizes, one-example inference and sequences. In distributed training, batch statistics may require communication across devices if a shared batch is used; layer statistics can be computed independently for each example or token.

Neither method guarantees better training. Layer normalisation removes information in the overall mean and scale of the selected features from the normalised values; learned affine parameters restore some flexibility but do not necessarily recover all input-dependent information. Very few or nearly constant features can make the statistics uninformative. The choice of axes changes the operation and its inductive effects.

Normalisation in different architectures

In a fully connected network, either method can be applied to hidden representations. Batch normalisation can work well with reasonably sized, representative batches. The two-dimensional matrix is useful for learning the idea, but real tensors often have more axes.

RepresentationOne group of valuesStatistics retained for
Fully connected $(B,M)$, batch normAll $B$ examplesEach feature $i$
Fully connected $(B,M)$, layer normAll $M$ featuresEach example $n$
Convolution $(B,C,H,W)$, batch normBatch and spatial axes $(B,H,W)$Each channel $c$
Sequence $(B,T,D)$, layer normFeature axis $D$Each example and token $(n,t)$

Convolutional batch normalisation commonly pools positions and examples per channel; spatial values need not be independent, even though they contribute to the same statistic. In recurrent networks, variable sequence lengths and recurrent computations can make batch-based statistics awkward; layer normalisation is an alternative that does not require other examples. Transformers commonly apply layer normalisation over the $D$ features of each token independently, rather than across time or across the batch. Other configurations are possible, so inspect the actual axes.

Why can normalisation help optimisation?

The original motivation for batch normalisation emphasised changes in intermediate distributions during training, called internal covariate shift. Subsequent research has questioned whether reducing that shift is the primary explanation. For example, Santurkar and colleagues studied smoother optimisation behaviour in particular settings. The effects are related and depend on the model and data; there is no single universal explanation.

Normalisation can change the geometry seen by the optimiser, reduce sensitivity to some parameter scales and help keep intermediate signals manageable. In some architectures it permits larger learning rates. Batch statistics add stochastic effects that may also affect learning. Recall the Hessian and condition number from the convergence note: changing the parameterisation or representation can change local curvature and how reliably a step follows the gradient. This does not make every objective convex or well-conditioned, nor does it guarantee better generalisation.

Initialisation and normalisation can complement each other: the former sets the starting signals, while the latter modifies intermediate computations throughout training. Neither removes the need for sensible initialisation, learning rates, optimiser choices or monitoring. Normalisation may help with some vanishing or exploding signal difficulties, but is not a universal cure for gradients.

Normalisation in practice

Check which dimensions contribute to each statistic: normalising a row instead of a column changes the model. Check placement too: pre-activations and post-activation values generally have different distributions. A positive $\epsilon$ keeps division finite when variance is small, though its size also changes the resulting variance when it is comparable to $\sigma^2$.

For batch normalisation, use training mode to update running estimates and evaluation mode to use them; keep those estimates with the learned model parameters. Small or unrepresentative batches can make training statistics unstable, and distribution shifts can make stored estimates less representative. Layer normalisation may be suitable when batches are small, but its feature grouping has its own consequences.

Scale and shift are trainable, so the final outputs are not constrained to have zero mean and unit variance. Internal normalisation also does not automatically replace input preprocessing: the input transformation influences the first computations, while internal layers act later. Finally, normalisation is part of the forward graph and influences gradients throughout the network, not merely the values displayed in a diagnostic plot.

Summary

Batch normalisation groups examples for each feature during training and normally uses stored running statistics at inference. Layer normalisation groups features for each example and uses the same kind of per-example calculation in both phases. Learnable scale and shift give both transformations additional flexibility. Their effects on optimisation depend on the architecture, data and chosen axes.
