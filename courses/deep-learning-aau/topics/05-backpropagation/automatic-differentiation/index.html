Automatic differentiation.

Follow derivatives through an evaluation graph in forward and reverse mode.

Four ways to obtain derivatives

We derived backpropagation by hand. This is one way to obtain an analytical derivative: work out a formula and implement it. Numerical differentiation instead estimates the derivative from nearby function values. Symbolic differentiation manipulates expressions to construct a new expression for the derivative. Automatic differentiation (AD) evaluates derivatives by applying the chain rule to the elementary operations actually executed by a program.

AD is not a finite-difference approximation: each operation supplies a local derivative rule, evaluated at the current values. Nor does it need to construct and simplify a symbolic formula for the whole function. Its computed values are nevertheless subject to ordinary floating-point rounding.

Symbolic derivatives can contain repeated copies of the same subexpression, making the resulting expression much larger than the original calculation. Reusing intermediate values avoids that duplication. An automatic differentiation system can also follow the operations executed through a loop or conditional, subject to the derivative rules for those operations; the derivative describes the executed computation at the current input. A change of branch or a nondifferentiable operation still requires care.

An evaluation trace

Consider the function used in Bishop and Bishop's discussion, $f(x_1,x_2)=x_1x_2+\exp(x_1x_2)-\sin(x_2)$. Reuse the product rather than calculating it twice:

$$v_1=x_1x_2,\quad v_2=\exp(v_1),\quad v_3=\sin(x_2),\quad f=v_1+v_2-v_3.$$

At $(x_1,x_2)=(1,0)$, the forward values are $(v_1,v_2,v_3,f)=(0,1,0,1)$. We use this point in both modes.

Forward-mode differentiation

A primal is an ordinary value; a tangent is its directional derivative along a chosen input direction $\dot{\mathbf x}$. For each operation, calculate its tangent from the input values and their tangents. Here,

$$\dot v_1=x_2\dot x_1+x_1\dot x_2,\quad \dot v_2=e^{v_1}\dot v_1,\quad \dot v_3=\cos(x_2)\dot x_2,\quad \dot f=\dot v_1+\dot v_2-\dot v_3.$$

Choose $\dot{\mathbf x}=(0,1)$ to differentiate with respect to $x_2$. At $(1,0)$ the tangents are $\dot v_1=1$, $\dot v_2=1$, $\dot v_3=1$ and $\dot f=1$. Seeding $(1,0)$ instead gives $\dot f=0$. In general, one pass calculates the Jacobian–vector product $\mathbf J\dot{\mathbf x}$, a directional derivative for every output. Forward mode is attractive when there are few input directions compared with the number of outputs.

Reverse-mode differentiation

An adjoint $\bar v$ denotes $\partial f/\partial v$ for an intermediate value. First run the ordinary forward calculation, then seed $\bar f=1$. Traverse operations backwards, adding contributions whenever a value feeds more than one operation. For this graph,

$$\bar v_2=1,\quad \bar v_3=-1,\quad \bar v_1=1+\bar v_2 e^{v_1}=1+e^{v_1},$$

$$\bar x_1=\bar v_1x_2,\qquad \bar x_2=\bar v_1x_1+\bar v_3\cos(x_2).$$

At $(1,0)$, $\bar v_1=2$, so $(\bar x_1,\bar x_2)=(0,1)$. Both input derivatives come from one backward pass. The direct contribution $1$ to $\bar v_1$ and the contribution through the exponential are added, just as downstream error signals were added in the network recursion. Backpropagation is reverse-mode AD applied to the network and loss.

Reverse mode computes a vector–Jacobian product. For a scalar loss, one reverse pass returns gradients for many parameters, which makes it especially useful in training. The backward rules may require forward values such as $e^{v_1}$; implementations retain them or recompute them. Retaining more values uses more memory, while recomputing can trade additional work for less storage.

Automatic differentiation in PyTorch

The following framework example extends the mathematical discussion with a practical implementation.

PyTorch records operations involving tensors that require gradients. This example evaluates the same function and differentiates its scalar result:

import torch

x = torch.tensor([1.0, 0.0], dtype=torch.float64, requires_grad=True)
v = x[0] * x[1]
f = v + torch.exp(v) - torch.sin(x[1])
f.backward()
print(f.item())  # 1.0
print(x.grad)    # tensor([0., 1.], dtype=torch.float64)

During backward(), the framework follows the recorded operations in reverse, applies their derivative rules and accumulates contributions into leaf tensors' .grad fields. Repeated calls accumulate gradients unless they are cleared. In a training loop, optimizer.zero_grad() clears them before a new calculation, loss.backward() calculates and accumulates them, and optimizer.step() updates parameters. These are distinct operations; calling backward() alone does not update the model.

Forward mode propagates a chosen input direction to all outputs; reverse mode propagates a chosen output weighting back to all inputs. The next note uses these products to discuss Jacobians and Hessians without necessarily constructing whole matrices.
