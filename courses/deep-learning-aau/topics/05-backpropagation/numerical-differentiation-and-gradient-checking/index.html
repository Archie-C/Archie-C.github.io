Numerical differentiation and gradient checking.

Approximate derivatives and use them to check a backward pass.

What this note covers

  • Finite differences
  • Why use backpropagation?
  • Checking the worked example

Finite differences

For a differentiable scalar function, the slope can be estimated from nearby function values. A forward difference uses

$$f'(x)\approx\frac{f(x+\epsilon)-f(x)}{\epsilon},$$

where $\epsilon>0$ is a small step. Taylor expansion gives $f(x+\epsilon)=f(x)+\epsilon f'(x)+\frac12\epsilon^2f''(x)+O(\epsilon^3)$, so the leading truncation error after division is $O(\epsilon)$. Evaluating on both sides gives the central difference

$$f'(x)\approx\frac{f(x+\epsilon)-f(x-\epsilon)}{2\epsilon}.$$

Since $f(x-\epsilon)=f(x)-\epsilon f'(x)+\frac12\epsilon^2f''(x)-\frac16\epsilon^3f^{(3)}(x)+O(\epsilon^4)$, the even-order terms cancel in the numerator. Under sufficient smoothness, the leading error after division is $O(\epsilon^2)$.

Making $\epsilon$ extremely small is not always better. Subtracting nearly equal floating-point values loses significant digits, and division by $\epsilon$ magnifies their rounding error. The best range depends on the function, parameter scale and precision.

For a parameter vector, the same construction changes one coordinate while keeping all others fixed. If $\mathbf e_j$ is the unit vector in coordinate $j$, then

$$\frac{\partial L}{\partial\theta_j}\approx\frac{L(\boldsymbol\theta+\epsilon\mathbf e_j)-L(\boldsymbol\theta-\epsilon\mathbf e_j)}{2\epsilon}.$$

Each evaluation must use the same data and the same definition of the objective. If the numerical calculation includes a penalty or averages over a batch, the analytical gradient must include that same penalty or average. Otherwise a discrepancy can reflect different objectives rather than an error in differentiation.

Why use backpropagation?

Suppose a standard feed-forward network has $P$ parameters and a forward evaluation takes $O(P)$ operations, with bounded-cost activation functions and an operation count proportional to its connections. Backpropagation traverses the same operations in reverse and calculates the full gradient in $O(P)$ time, up to a constant factor. A central difference needs two forward evaluations per parameter, or $O(P)$ evaluations and $O(P^2)$ total work. These estimates can change for networks whose operation count is not proportional to the number of distinct parameters, such as models with shared weights, or when batch size is varied.

Checking the worked example

Numerical differentiation is useful as an independent check, even though it is too expensive for ordinary training. Perturb just one parameter at a time, recompute the loss on each side, and compare the central difference with its backpropagated gradient. For the preceding network, the first output weight has analytical gradient $-0.369452\ldots$. The following self-contained code checks all nine parameters in double precision:

import numpy as np

x = np.array([1., 2.])
y = 0.5
# W1 (4 entries), b1 (2), W2 (2), b2 (1)
theta = np.array([.5, 0., 0., .5, 0., 0., 1., -1., 0.])

def loss(theta):
    W1, b1, W2, b2 = theta[:4].reshape(2, 2), theta[4:6], theta[6:8], theta[8]
    a = np.tanh(W1 @ x + b1)
    return 0.5 * (W2 @ a + b2 - y) ** 2

a = np.tanh(theta[:4].reshape(2, 2) @ x + theta[4:6])
d2 = theta[6:8] @ a + theta[8] - y
d1 = (1 - a**2) * theta[6:8] * d2
analytic = np.r_[np.outer(d1, x).ravel(), d1, d2*a, d2]
eps = 1e-5
numeric = np.empty_like(theta)
for i in range(theta.size):
    step = np.zeros_like(theta)
    step[i] = eps
    numeric[i] = (loss(theta + step) - loss(theta - step)) / (2 * eps)
relative_error = np.linalg.norm(analytic - numeric) / max(
    1e-12, np.linalg.norm(analytic) + np.linalg.norm(numeric))
print(relative_error)

This norm-based relative error compares the difference with the scale of both gradients; the small denominator floor handles values near zero. In float64 a smooth example with this step should typically give an error well below $10^{-7}$, but tolerances are problem-dependent. Inspect individual absolute errors near zero too. Float32 often needs a larger step and looser tolerance. Mismatched loss reductions, omitted bias terms, stale gradients, random dropout, changing batch statistics, and nondifferentiable points can all produce discrepancies. Fix random state or disable stochastic operations during a check.
