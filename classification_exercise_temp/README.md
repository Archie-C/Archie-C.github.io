# Rocket landing expert

The active controller is `ExpertController` in `rocket_expert.py`. It observes the 12 values of `observation-v1.0`, chooses an integer action from 0–9, and replans at each control boundary. The simulator and `touchdown-v1.0` scorer remain authoritative. Success means candidate-safe **first contact**, not post-impact stability.

Install the dependencies with `python3 -m pip install -r requirements.txt`. Run a predeclared held-out random comparison and open any resulting `.json` replay in the flight lab:

```sh
python3 rocket_expert_evaluate.py results/held-out
python3 rocket_server.py
```

The first command samples 100 starts per tier using seed `964731` and evaluates the same starts at 0.10, 0.05 and 0.02 seconds. It writes `summary.json` and one complete replay per attempt. This is computationally expensive. Use `--per-tier 1` for a smoke test or `--set regression` for the fixed diagnostic and historical feasibility cases; `--interval 0.05` selects one interval. A smaller run is not the held-out evaluation. Choose a new output directory for each run.

The independent physics timestep remains 0.01 s. The existing 0.10 s default is retained provisionally until the full interval comparison is complete; it is not a claim that this interval is best. Construct a controller using `ExpertController(control_interval=interval)`, pass `expert.predict_action` to `evaluate_closed_loop` with matching calibrated parameters, and call `reset()` for a fresh run (the runner resets bound controllers automatically).

The sampler varies offset, altitude, both velocities, attitude, rotation and fuel across nominal, challenging and extreme tiers, alternating the calibrated zero-wind and crosswind environments. Its initial states must remain within the calibrated envelope: COM altitude 0–1000 m, airspeed at most 130 m/s, and absolute angle of attack at most 35°. Excursions during flight are recorded, not clamped. No feasibility solver is used; a failed landing does not establish that the starting state is unrecoverable. Mean successful quality is null when there are no successes. Failure reasons can overlap. Optimisation uses a fixed candidate/horizon work budget and no wall-clock timeout. On a search failure the deterministic guidance quantisation is used and recorded as a fallback.

Run focused checks with:

```sh
python3 -m unittest test_expert_simplification test_rocket_physics test_scoring test_calibration
```

Frozen source versions, datasets, benchmark reports, and replays remain historical artifacts. The earlier documentation, including calibration provenance and previous experimental commands, is preserved in [archive/README-historical.md](archive/README-historical.md); those commands and controller comparisons are not the supported workflow for this milestone. The historic 12/12 feasibility result does not demonstrate broad robustness. No dataset is generated by the evaluation command.
