# Rocket landing expert

The active controller is `ExpertController` in `rocket_expert.py`. It observes the 12 values of `observation-v1.0`, chooses an integer action from 0–9, and replans at each control boundary. The simulator and `touchdown-v1.0` scorer remain authoritative. Success means candidate-safe **first contact**, not post-impact stability.

Install the dependencies with `python3 -m pip install -r requirements.txt`. Run a predeclared held-out random comparison and open any resulting `.json` replay in the flight lab:

```sh
python3 rocket_expert_evaluate.py results/held-out
python3 rocket_server.py
```

The first command samples 100 starts per tier using seed `964731` and evaluates the same starts at 0.10, 0.05 and 0.02 seconds. It writes `summary.json` after each completed attempt and one complete replay per attempt. This is computationally expensive; `--workers 4` runs independent attempts in parallel. A partial summary is explicitly marked incomplete; repeat the same command with `--resume` to continue it after interruption. Use `--per-tier 1` for a smoke test or `--set regression` for the fixed diagnostic and historical feasibility cases; `--interval 0.05` selects one interval. A smaller run is not the held-out evaluation. Choose a new output directory for each run.

The independent physics timestep remains 0.01 s. The selected default is 0.10 s. On the predeclared 300-start held-out set it produced 241 candidate-safe contacts, compared with 238 at 0.05 s and 237 at 0.02 s, while requiring the fewest decisions and fallbacks. The 0.05 s interval had higher mean quality among successes. [Recorded metrics](benchmarks/expert-simplification-v1-summary.json) include per-tier rates, switching and compute cost; the complete report and replays are in `results/held-out`. These results do not prove feasibility or safety outside this model and sample. Construct a controller using `ExpertController(control_interval=interval)`, pass `expert.predict_action` to `evaluate_closed_loop` with matching calibrated parameters, and call `reset()` for a fresh run (the runner resets bound controllers automatically).

The sampler varies offset, altitude, both velocities, attitude, rotation and fuel across nominal, challenging and extreme tiers, alternating the calibrated zero-wind and crosswind environments. Its initial states must remain within the calibrated envelope: COM altitude 0–1000 m, airspeed at most 130 m/s, and absolute angle of attack at most 35°. Excursions during flight are recorded, not clamped. No feasibility solver is used; a failed landing does not establish that the starting state is unrecoverable. Mean successful quality is null when there are no successes. Failure reasons can overlap. Optimisation uses a fixed candidate/horizon work budget and no wall-clock timeout. On a search failure the deterministic guidance quantisation is used and recorded as a fallback.

Run focused checks with:

```sh
python3 -m unittest test_expert_simplification test_rocket_physics test_scoring test_calibration
```
